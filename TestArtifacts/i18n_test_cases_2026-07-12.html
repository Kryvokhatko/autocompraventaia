1. Summary

7 confirmed defects from a session-based exploratory walkthrough across English, Spanish, and German locales (Landmark, Sabotage, Consistency, and Location tours). All were independently reproduced by re-navigating the live site.

Assumptions: the nav bar / footer link translations (which do work correctly) represent the site's actual localization intent — used as the oracle for correct output where no written spec exists. German date convention (DD.MM.YYYY) and Spanish decimal-comma convention are assumed as the correct target formats. Locale is determined by the ?_locale= query parameter.

Open ambiguities: whether the "paid X min" trial-countdown wording is intentional; whether the Stripe-hosted checkout is expected to render in the site's active locale or is accepted as English-only by design.

4. Test Cases

TC-AUTH-001Fail — D-02
Login form renders in Spanish under ES locale
Traces to: TCOND-01 / R-LOC-01 (High)Priority: HighTechnique: Equivalence Partitioning (locale classes)
Steps
  1. Navigate to the login page with Spanish selected
  2. Observe heading, field labels, submit button, OAuth link, "already have an account" link
Expected

Heading "Iniciar sesión"; labels "Correo electrónico"/"Contraseña"; button "Iniciar sesión"; Google link and "already have an account" link in Spanish; nav bar matches Spanish throughout.

Actual

Heading, labels, and button all in English ("Please sign in", "Email address", "Password", "Sign in"). Nav bar correctly Spanish, confirming the defect is isolated to the form component.

TC-API-001Fail — D-01
Favorites-count API does not throw a client-side error for unauthenticated users
Traces to: TCOND-04 / R-API-01 (Medium)Priority: MediumTechnique: Error Guessing + Equivalence Partitioning (locale classes)
Steps
  1. Open a clean, logged-out session
  2. Load the home page under each of the 3 in-scope locales
  3. Open the browser console; inspect requests to the favorites-count endpoint
Expected

No console errors on page load; the endpoint returns valid JSON or the client skips the call while unauthenticated.

Actual

Console error thrown attempting to parse an HTML login-redirect response as JSON. The endpoint returns a redirect instead of JSON for logged-out visitors; the behavior is locale-independent.

6. Regression Impact

All defects sit in shared/global components (translation resolution, a shared auth-form component, a shared payments-formatting utility, a shared branding partial) rather than isolated one-off pages. The auth-form and branding-partial fixes touch code paths rendered on every page load across all locales. The payments-formatting fix touches a shared currency/date utility likely reused elsewhere (e.g. plan comparison, invoices) — worth checking for other call sites once fixed.
