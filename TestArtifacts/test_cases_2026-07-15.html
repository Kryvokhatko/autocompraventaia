1. Summary

Full-site coverage (all major workflows), English/Spanish/German locales only. 19 flows were walked; 13 defects are tracked against this site — 9 carried forward from 2026-07-12 (7 re-confirmed present, 2 not re-checked this session) and 4 newly discovered.

Assumptions: pages that consistently redirect an unauthenticated visitor to login (Offers, Map, Top Sales, Below-Market, Payments) are treated as intentionally gated paid/account features, not defects. The 11 favorites pre-loaded on every fresh trial account are confirmed identical sample/demo data, not user-specific data.

Open ambiguities: whether the below-market page is intentionally Spanish-only or should receive full EN/DE localization; whether the repeated 410/404 resource errors on Analytics reflect expected data lifecycle or a backend cleanup gap; whether Terms of Service is deliberately restricted to logged-in users.

TC-AUTH-003Pass
New user can register with email/password and reach the dashboard with an active trial
Traces to: TCOND-09 / R-FUNC-01 (High)Priority: HighTechnique: Use Case Testing + Equivalence Partitioning
Steps
  1. Navigate to Register
  2. Fill in a valid, unused email and password
  3. Submit the form
Expected

Redirect to the Offers dashboard; a trial-status indicator appears in the nav; no registration-flow console errors.

Actual

Registration succeeded and redirected as expected. The trial badge appeared and correctly counted down across page navigations. No registration-flow console errors (the separately-tracked favorites-count error is unrelated to this flow).

TC-AUTH-005Pass (1 new accessibility finding)
Login form handles invalid input safely (wrong password, empty submit, malformed email)
Traces to: TCOND-10 / R-FUNC-01 (High)Priority: MediumTechnique: Error Guessing + Equivalence Partitioning
Steps
  1. Case A: incorrect email/password, submit
  2. Case B: empty form, submit
  3. Case C: malformed email (no "@"), submit
Expected

TC-FAV-002Fail — D-13
Favorites-count badge updates immediately after removing a favorite, without a page reload
Traces to: TCOND-19 / R-FUNC-01 (High)Priority: LowTechnique: Use Case Testing (state-change verification)
Steps
  1. Note the badge value on Favorites
  2. Remove one favorite and accept the confirm dialog
  3. Observe the badge without reloading
  4. Reload and observe again
Expected

The badge updates to the new count promptly, without a reload.

Actual

Confirm dialog reads "Delete this car from favorites?" The removal is correctly persisted (10 remaining after reload). The badge, however, stays at the pre-removal value for several seconds on the same page and only updates after a reload.
